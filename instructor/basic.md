# Basicは、説明より操作を先に置いて30分で完走する

Basicの主メッセージは「実装前に調査とPlan、実装後にdiffとbuild」です。機能を網羅せず、この流れを1回完走することを優先します。

## 0:00〜0:03 完成前のLPを見せる

TaskFlow AIのLPを開き、Hero、Features、How it works、CTAがあることを見せます。FAQがないことだけを演習課題として伝えます。

講師の一言:

> 今日はAIにLPを丸ごと作らせません。今あるコードを調べ、計画を確認し、小さく変更して、結果を確かめるところまで進めます。

## 0:03〜0:08 Claude Codeに調査させる

[Mission 1](../docs/01-basic/01-explore.md)のプロンプトを実行します。回答が長くなった場合は、根拠ファイルを4つに絞らせます。

確認ポイント:

- 参加者が正しいディレクトリで `claude` を起動した
- 回答にファイル名が含まれる
- Claude Codeがコードを編集していない

## 0:08〜0:14 曖昧な指示を分解する

[Mission 2](../docs/01-basic/02-prompt.md)を進めます。「いい感じ」の不足を参加者から2〜3個挙げてもらい、目的・要件・制約に整理します。

時間をかけすぎないため、FAQの文言検討は教材の要件をそのまま使います。

## 0:14〜0:21 Plan modeから実装する

Plan modeへ切り替え、変更ファイルとHTML構造を確認します。`details` / `summary` 案が出なかった場合は、標準HTMLで開閉できないか質問します。

通常モードへ戻して実装させます。権限確認では、対象ファイルとコマンドを声に出して確認します。

## 0:21〜0:27 diffとbuildを確認する

参加者と一緒に次の順で確認します。

```bash
git status --short
git diff --stat
git diff
npm run build
```

HTMLの文言を細かく読む前に、想定外のファイルと変更量を見る習慣を強調します。

## 0:27〜0:30 CLAUDE.mdで種明かしする

ルートの `CLAUDE.md` を開きます。既存デザイン、依存追加、レスポンシブ、検証のルールが、毎回の長いプロンプトを減らしていることを説明します。

締めの一言:

> Claude Codeに任せる範囲は、調査、計画、実装、確認の各段階で選べます。まず調べてもらい、計画を読み、差分を確認する。この順番を持ち帰ってください。

## 5分以上遅れたときの短縮箇所

- 曖昧なプロンプトの実演を省き、違いだけ口頭で説明する
- FAQ文言は教材からコピーする
- CSSの微調整は実装例を部分的に使う
- CLAUDE.mdはRulesとの違いを扱わず、用途だけ伝える

Plan modeとdiff確認は省略しません。この2点がBasicの学習目標だからです。
