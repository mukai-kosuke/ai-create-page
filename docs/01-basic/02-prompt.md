# Mission 2: 「いい感じ」を、目的・要件・制約へ分解する

まず、次の曖昧な依頼を見ます。実行はせず、どこが判断できないかをClaude Codeへ質問してください。

```text
このLPをいい感じに改善してください。
まだ実装せず、判断できない点を挙げてください。
```

「誰のためか」「何を改善したいか」「どこまで変えてよいか」が不足しているとわかります。続けて、FAQ追加の依頼へ具体化します。

```text
FAQセクションを追加したいです。

目的:
導入前のユーザーが持つ不安を、CTAへ進む前に解消する。

要件:
- 質問は3項目
- 料金、解約、チーム利用について答える
- 質問をクリックすると回答が開閉する
- キーボードでも操作できる
- 既存デザインに合わせる
- 幅390px前後でも読みやすくする

制約:
- 新しいライブラリは追加しない
- 既存のCSS Variablesを優先する
- FAQ以外の文言や構造は変更しない

まだ実装せず、現在のコードを調査して実装方針を考えてください。
```

良い指示は、見た目を細かく命令することではありません。目的、完成条件、変更してよい範囲を渡し、残りの判断材料をClaude Codeに調査させます。

計画に不足があれば、実装前に修正します。

```text
その計画で、次の2点をもう少し具体化してください。
- 変更するファイル
- アクセシビリティを保つHTML構造
```

計画が納得できる内容になったら、次のMissionでPlan modeを使います。
