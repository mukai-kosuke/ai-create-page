# Mission 4: diffとビルド結果を見てから、変更を採用する

AIが「完了しました」と答えても、変更内容と検証結果は分けて確認します。まずClaude Codeへ依頼します。

```text
今回のgit diffをレビューしてください。

次の観点で確認してください。
- FAQ以外へ不要な変更がないか
- 要件の3項目を満たしているか
- 既存のCSS Variablesを使っているか
- キーボード操作を壊していないか
- モバイルで横にはみ出す指定がないか

問題があれば、修正前に指摘だけを示してください。
```

自分でもターミナルから確認します。

```bash
git status --short
git diff --stat
git diff
npm run build
```

## 差分を読むときの順番

1. `git status --short` で、想定外のファイルが増えていないかを見る
2. `git diff --stat` で、変更量が依頼に対して大きすぎないかを見る
3. `git diff` で、HTMLとCSSの内容を読む
4. `npm run build` で、構文と生成処理が通ることを確かめる

問題が見つかった場合は、現象と期待する状態を伝えます。

```text
幅390pxではFAQの左右余白が狭すぎます。
既存のモバイル余白に合わせる修正案を示し、FAQのCSSだけを直してください。
```

## 最後にCLAUDE.mdを読む

ルートの `CLAUDE.md` には、既存デザインを優先すること、依存ライブラリを無断で増やさないこと、変更後に検証することが書かれています。毎回の依頼に繰り返し書くプロジェクトルールは、ここへ置けます。

Basicのゴールは、Claude Codeに実装させることだけではありません。調査、計画、差分確認、ビルドをひと続きの作業として扱えるようになることです。
